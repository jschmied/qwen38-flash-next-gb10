## 1. Who drives the loop

- [V] Draft decode modes (AR:157-182): global FULL → FULL_DECODE_ONLY; **PIECEWISE (prod) → NONE, so steps 2..K run eager, every kernel launched from Python**; FNDRAFTPW forces PIECEWISE. The fused whole-loop graph (AR:608-695) is **off on our stack**: the journal says "Fused multi-step draft decode is not supported by … QWEN4_EXP_EXP_QSA_STATE" (Sep 25 runs). So even under FULL, the host launches one graph per step.
- [V] The FNDYN patch is in this venv (AR:28-57, 555-606). Its `float(_fn_cum.max())` at AR:566 is the per-step sync. It also never trims verify: it pads the tail with copies of the last token (AR:567).
- [V] The verify shape is fixed **on the host**: `num_toks` (MR:1218, AV `get_num_tokens` MR:1244-1247) chooses the target batch descriptor/graph. With AV off it is scheduled tokens = 1+K. AV (the DSpark/"enable_adaptive_verification" path) trims on the host from **stale** confidences (AV:320, 2-slot pinned copy AV:168-181, 265-291). A GPU pass then redistributes the budget per request (AV:403-458, MR:1354) with a device-side `query_start_loc` and `cu_num_logits`. **So varlen verify with device-side lengths already exists (FNAVPW made it run on PIECEWISE), but the total token count always comes from the host.**
- [V] AV never shortens the draft loop: propose always drafts K.

## 2. Options
(a) **CUDA graph IF nodes.** [V] torch 2.13 has `CUDAGraph.begin_capture_to_if_node(pred)` / `end_capture_to_conditional_node()` (torch/_C/__init__.pyi:11916-7; torch/_higher_order_ops/cudagraph_conditional_nodes.py:95-130). It has **no WHILE**, but monotone IFs are enough. libtorch_cuda rejects "RNG within data-dependent conditional nodes"; our gumbel sampling is Triton `tl.rand`/murmur with an explicit seed (v1/worker/gpu/sample/gumbel.py:66-136), so it does not trip that check [V]. What blocks it: a body must sit inside a **FULL** capture, and prod draft steps are eager (AR:166-175). Getting there needs FDO globally, or a local "FULL for draft decode only" override. The det-202 memory says FDO ran on this model and was null vs PIECEWISE, so capture works [V-memory; not re-checked on K=5/RecoverSSM/FNNVFP4]. CUDA restricts what a body may contain (kernels, memcpy/memset, child/conditional nodes; no event-record/host/alloc nodes) [D]. The offloader copy-stream fork/join around capture (v1/worker/gpu/cudagraph_utils.py:466-482) and the PLE path are the likely violators [G]. Torch also warns that `graph_capture_record_stream_reuse` is incompatible [V string]. A skipped step still costs the host metadata rebuild plus one graph launch (~tens of µs [G]). **Feasible, 150-250 LOC, medium-high risk.**
(b) **Device predication in every kernel.** Impractical: CUTLASS NVFP4, FlashInfer/QSA, and the Triton GDN kernels would all need a flag. One partial form is free, though: the MoE routers already honour a device `is_padding` mask, setting topk_id to -1 and the weight to 0 (model_executor/layers/fused_moe/router/fused_topk_router.py:21-58; qwen4_exp uses Qwen3NextSparseMoeBlock → FusedMoE [V]). Marking a stopped row as padding skips its routed-expert reads. In eager mode it saves **no launches**, so it helps only if draft steps are GPU-bound. That is unmeasured: c=1 is 54 % GPU busy (decode-c1-idle memory), and the eager draft step is probably launch-bound [G]. Also unverified: that the NVFP4 MoE backend skips -1 cleanly (see b12x-50189 memory).
(c) **Lagged host decision. RECOMMENDED FIRST.** Choose K_{n+1} on the host from data that has already landed. That removes launches, GPU work and verify rows consistently, with zero syncs, and works under PIECEWISE/eager. The async read already exists: the AV pinned 2-slot copy on a side stream (AV:283-291). `event.query()` gives a non-blocking check for round n; if it has not landed, fall back to round n-1, which is always ready. SGLang ships the same idea: an EMA of accept length switches among pre-captured step-count tiers [D: docs.sglang.io adaptive_speculative_decoding; issue #21459]. **Low risk, 60-90 LOC.** Its value is unknown until an offline replay is run.
   Variant: one sync per round, right after the draft prefill (p1 known), instead of one per step [G]. It costs about one sync (≈ a draft step, §5b) and wins only when it stops ≥2 steps early. Replay it as a policy, but do not build it first.
(d) **Draft all K, trim verify on device.** Already capped at +1.8/+4 %. The device-only version is worse: keeping host shape 1+K and trimming via AV capacities plus a device `is_padding` recovers only the MoE part of a 3.3 ms row, because dense, attention and GDN still run on the padded rows [G].
(e) Field. [D] TRT-LLM one-model spec runs the whole draft+verify loop in one graph at a fixed length. SGLang: fixed `num_steps` per captured graph, adaptive = host EMA tier switch; confidence pruning only trims which tree nodes get verified. vLLM DSpark AV = host-stale budget + device realloc (above). No engine found does an in-graph data-dependent draft stop.

## 3. Sketch of (c)
1. SP `sample_draft` (SP:412-438), plus qwen4_exp/nvidia/mtp.py:523/531: write p1 = max softmax of the slice into `draft_token_confidence_probs[:, step]` on every path (device only). Today only the estimator fills it (SP:441-454), and SP:242-248 forbids the estimator together with local-argmax. ~15 LOC.
2. AR `_multi_step_decode`: delete the FNDYN sync (AR:560-570). Take `k_run = self._k_plan` (host int) before the loop and run `range(1, k_run)`. Write 0 into `confidence_probs[:, k_run:]` on device so AV never admits a slot that was not drafted, and keep the tail-copy for `draft_tokens`. ~20 LOC.
3. Policy (new, ~30 LOC, called at propose start): read the landed pinned slot. `k_plan = 1 + #leading positions with cumprod ≥ τ`, grow by +1 when every drafted conf ≥ τ (without this, censoring means it never regrows), floor 1. Store per request.
4. AV `get_num_tokens` (AV:309-313): `scheduled_drafts = min(len(drafts), k_plan[slot])`. This is host-known, so batch_desc, the PW graph size and `max_query_len` stay exact. Requires AV (FNAVPW) on. ~10 LOC. c=1 sizes 1..6 already fall under the capture sizes [1,2,4,8].
**Gate before coding:** replay the FNDYN/accept logs *with censoring* (only drafted positions are observable). Cost model: 1.3 ms per draft step + 3.3 ms per verify row + base.
