Same failure here on main with a ModelOpt mixed-precision checkpoint (FP8 body + NVFP4 experts) on a GB10. Cause: `_get_ple_embedding_quant_method()` in `vllm/models/qwen4_exp/nvidia/ple_layer.py` returns the FP8 embedding method only for `Fp8Config`; ModelOpt checkpoints ship the PLE in exactly the format that method implements (F8_E4M3 shards + one global `ngram_embedding.weight_scale`), so the parameter is never created and shard 203 fails.

Minimal fix that loads for us: accept the ModelOpt config names in that gate and return `Qwen4ExpPLEFp8EmbeddingMethod()` — env-gated script here: https://github.com/jschmied/qwen38-flash-next-gb10/blob/main/tools/main/ple_gate_patch.py (a port of the same fix we carried on the pre-merge preview since 08-27). Can turn it into a PR if a maintainer prefers that over widening the gate inline.
