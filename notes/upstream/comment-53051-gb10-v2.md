So on V2 the misclassification does not occur, and it cannot by construction: `get_uniform_decode_token_count(num_reqs, num_tokens, max_query_len, has_prefill)` returns `None` whenever `has_prefill` is set, and the runner sets it from `num_computed_prefill_tokens < prefill_len`, not from the batch shape. The shape-only `_is_uniform_decode` in `gpu_model_runner.py` (V1) is the affected path that #53059 fixes — consistent with the earlier "does not reproduce on GB10 / sm_121 with PIECEWISE" report here, which was also a V2 stack.

One caveat for anyone repeating this on hybrid models: the 3–8-token prompts differ between repetitions at temperature 0 in both arms (from the second generated token). That is the near-tie nondeterminism tracked in #54521, not state loss — the outputs are fluent and the acceptance rate is normal — and a 3-token prompt maximises it because there is no context to break ties.
