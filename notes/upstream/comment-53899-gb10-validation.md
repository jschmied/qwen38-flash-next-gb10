GB10 (DGX Spark, sm_121, 1 GPU, 128 GB unified) validation of this PR's `vllm/` side on top of today's nightly (`0.28.1rc1.dev352`), with a ModelOpt mixed-precision checkpoint (NVFP4 experts + FP8_PB_WO dense projections + FP8 lm_head, F8 PLE shards with one global `weight_scale`):

- 13 of the 14 `vllm/` files apply cleanly; in `ple_layer.py` three hunks conflict with #54517 (the fused PLE ops merged 09-02): `compute_ngram_ids` (main has no static padded buffer any more, the narrowing hunk is moot), `forward` → `forward_impl` (main's fused custom-op path has to stay for the GPU worker; the offload branch goes next to it), and the `Qwen4ExpPLELayer.__init__` block (main's constructor lost the `max_num_*` args). - With that, the offload worker spawns, discovers the one `PleOffloadLayer`, loads the 47.7 GiB tables unpinned, and the model serves: 69.8 GiB on the GPU, 508 s load, coherent output, TTFT 2.80 s at 7.5k tokens / 10.87 s at 29k (batch 4096, no spec, prefix cache off) — within 1–2 % of the pre-merge preview image on the same box, i.e. this PR restores the memory shape GB10 needs (pinning the tables via UVA offload thrashes the box instead).
