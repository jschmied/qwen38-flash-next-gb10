Possibly the same class as what we just root-caused on a GB10 for Qwen3.8-Flash-Next (#55357 → #55467): with speculative decoding configured the Mamba block table has `1 + num_speculative_blocks` columns, the base Mamba metadata builder passes the prefill state slots as the strided column view `state_indices_tensor_p[:, 0]`, and a kernel that indexes that vector with unit stride resolves request r ≥ 1 to request 0's speculative checkpoint blocks. The signature is "wrong for a subset of requests, only with speculation configured, only when several requests share a step" — batch row 0 is right, the following rows are not. In our case the consumer was the PLE short-conv kernel; the GDN kernels on the NVIDIA side take a stride (see #51682), so for a 27B hybrid the consumer would be a different one, but the `prompt_logprobs` path under MTP with chunked prefill is worth checking for the same assumption. Happy to run a specific configuration on this box.
