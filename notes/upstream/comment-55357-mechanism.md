Found it, and it is not the drafter. With MTP merely *configured* the corruption reproduces even when the draft forward is skipped entirely (zero drafts returned) — 1/10 pairs at c=2 — and the batch-composition log makes the trigger exact: a step whose batch is prefills only corrupts every prefill after batch row 0 (5/5 such steps), while the same two prefills behind a speculating decode row are clean (3/3).

Root cause: with speculation configured the Mamba block table has `1 + num_speculative_blocks` columns per request, and the base Mamba metadata builder passes the prefill state slots as the strided column view `state_indices_tensor_p[:, 0]` (`mamba_attn.py`). The PLE short-conv kernels load the slot with a unit stride (`tl.load(state_idx_ptr + r)`, `ops/ple.py`), so prefill row r ≥ 1 resolves `block_table[0, r]` — request 0's speculative checkpoint blocks. The conv state is written there, overwritten by request 0's speculative steps, and the request then decodes from its own never-written slot: correct first token, garbage from the second, acceptance collapse downstream. Row 0 survives; with four columns rows 1–3 die and row 4 lands in request 1's unused primary block and survives, which matches the 3/2 split we measured at c=5. Without speculation the view is contiguous (one column); with a spec row in the batch the spec branch gathers indices with advanced indexing (contiguous) — hence your "episodic": it needs two prompts to land in one prefill-only step.

Fix: pass the stride to the two kernels — PR #NNNNN, with a unit test that runs the prefill store with a strided and a contiguous index vector. On this box the fix takes the corrupted-cell rate from 30–50 % to **0 of 20 cells** (`temperature 0`, simultaneous pairs, triples and fives, 128 tokens); the log confirms the vector arrives with stride 4 (= 1 + num_speculative_tokens) in prefill and decode mode.

Your Gemma 4 observation would be a different mechanism (no PLE layer there); this one is specific to the Qwen4-exp PLE short conv, but any other short-conv consumer of `state_indices_tensor_p` that assumes unit stride would fail the same way under speculation.
