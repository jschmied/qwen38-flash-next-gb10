POSTED 2026-09-05 18:4x as https://github.com/vllm-project/vllm/issues/54764#issuecomment-5553280108. Comment on vllm#54764 (PLE batched prefill pads to batch-max query length → transient OOM).

Confirming the "should be fixed by #54517" note from the source: on current `main` the PLE prefill path no longer builds the `(num_prefills, max_prefill_query_len, hc_hidden_size)` slot matrix at all. `Qwen4ExpPLELayer._short_conv_dilated_dispatch` hands the flat `[num_tokens, C]` activations to the fused Triton kernels (`ops/ple.py`, `mode="prefill"`), which walk each request by `query_start_loc`; there is no `packed_tokens`, no `.transpose(1, 2).contiguous()` copy and no `history` cat. The only remnant is `max_prefill_query_len` in the short-conv metadata builder (`short_conv_attn.py`), which the layer no longer consumes. So the activation peak of a mixed-length step is back to being linear in the scheduled tokens, not `num_prefills × batch_max`. If the reporter can reproduce the scheduler shape from the issue on a nightly after 2026-08-31 without the OOM, this can close.
